================================================================================
  2. ITEM TYPE SYSTEM & resourcePath (CRITICAL)
================================================================================

  Every item ScriptableObject has a "resourcePath" field. This MUST be set
  to the correct value or your item WILL NOT appear in the game.

  The game discovers mod assets by type — your folder structure inside the
  AssetBundle does not matter. However, resourcePath is used to classify
  which equipment slot an item belongs to and to build save/load paths.
  You can organise your project folders however you like.

  VALID resourcePath VALUES:
  -------------------------------------------------------------------------
  | Item Slot          | resourcePath                                     |
  |--------------------|-------------------------------------------------|
  | Resource           | Base/Items/Resource                              |
  | Consumable         | Base/Items/Consumable                            |
  | Shield             | Base/Items/Shield                                |
  | Thruster           | Base/Items/Thruster                              |
  | Primary Weapon     | Base/Items/PrimaryWeapon                         |
  | Secondary Weapon   | Base/Items/SecondaryWeapon                       |
  | Special            | Base/Items/Special                               |
  | Auto Special       | Base/Items/AutoSpecial                           |
  | Utility            | Base/Items/Utility                               |
  | Passive            | Base/Items/Passive                               |
  | Schematics         | Base/Items/Schematics                            |
  -------------------------------------------------------------------------

  If resourcePath is wrong or empty, the item will load but never appear
  in any equipment list, shop, or drop table.

  EXAMPLE: A secondary weapon launcher must have:
    resourcePath = "Base/Items/SecondaryWeapon"


================================================================================
  3. SCRIPTABLEOBJECT HIERARCHY
================================================================================

  All item ScriptableObjects inherit from a class hierarchy. Each level adds
  fields. When you create a "Launcher - Basic", it has ALL fields from:
    ItemBase > EquippableItemBase > ActivatableItemBase > LauncherItemBase
    > BasicLauncherItemBase

  Hierarchy:
  ----------
  ItemBase (all items)
    |
    +-- ConsumableItemBase
    +-- ResourceItemBase
    |
    +-- EquippableItemBase (equippable items)
        |
        +-- ShieldItemBase
        +-- ThrusterItemBase
        +-- StaticUpgradeItemBase (passive upgrades)
        +-- SchematicsItemBase
        +-- EnrageReplaceItemBase
        |
        +-- ActivatableItemBase (items with an activate button)
            |
            +-- DroneDropperItemBase
            +-- TurretDropperItemBase
            +-- ShipSpawnerItemBase
            +-- PulseItemBase
            +-- ShieldWardItemBase
            +-- LaserSpinnerItemBase
            +-- PhaseShiftItemBase
            +-- PhasePlaceholderItemBase
            +-- TemporalDriveItemBase
            +-- GrappleGunItemBase
            |
            +-- LauncherItemBase (projectile weapons)
            |   |
            |   +-- BasicLauncherItemBase
            |   +-- ScatterLauncherItemBase
            |   +-- MissileLauncherItemBase
            |   +-- ChargingLauncherItemBase
            |   +-- MineLauncherItemBase
            |   +-- LeechLauncherItemBase
            |   +-- OrbLauncherItemBase
            |   +-- ToggleLauncherItemBase
            |   +-- SpinalLauncherItemBase
            |   +-- ReboundLauncherItemBase
            |   +-- AutoBasicLauncherItemBase
            |   +-- AutoMissileLauncherItemBase
            |
            +-- BeamWeaponItemBase (beam/laser weapons)
                |
                +-- LaserItemBase
                +-- AutoLaserItemBase
                +-- LeechLaserItemBase
                +-- RepairLaserItemBase
                +-- SpinalLaserItemBase
                +-- PointDefenseLaserItemBase


================================================================================
  4. BASE CLASS FIELDS (inherited by all items)
================================================================================

  --- ItemBase fields (ALL items have these) ---

  resourcePath          string    REQUIRED. See section 2 for valid values.
  languageKey           string    REQUIRED. Unique key for translations.
                                  Click "Generate Language Key" for a random one.
                                  Language entries use: <key>.name and <key>.desc
  description           string    Item description (used for language generation).
  designNotes           string    Internal notes (not shown to players).
  minimumLevel          int       Minimum player level to find/use this item (1+).
  forSaleStarMaps       string[]  Star map IDs where this item is sold.
  forSaleFlagship       bool      Whether this item is sold on the Flagship.
  factionImages         FactionImage[]  Icons per faction (see section 14).
  containerPrefab       GameObject      Floating pickup prefab in space.

  --- EquippableItemBase fields (shields, weapons, thrusters, etc.) ---

  npcUseOnly            bool      If true, only NPCs can use this item.
                                  It won't appear in player equipment lists.
  noSandbox             bool      If true, hidden from the Sandbox ship designer.
  allowInvisible        bool      Whether the item works while ship is invisible.
  npcPlayerAlternative  EquippableItemBase  If npcUseOnly, this item drops for
                                            players instead.
  gameObjectPrefab      GameObject  REQUIRED. The equippable prefab that gets
                                    attached to the ship. For weapons, this is
                                    the gun model with muzzle flash children.

  --- ActivatableItemBase fields (items with activate button) ---

  activatableIcons      FactionImage[]  Icons shown on the action bar per faction.
  hueShiftIcon          bool      Whether the icon should be hue-shifted to
                                  match the player's faction colour.
  targetFriendly        bool      If true, targets friendly ships (e.g., repair).
  playCooldownSound     bool      Whether to play the cooldown-ready sound.
                                  Default: true.


================================================================================
  5. WEAPON TYPES - LAUNCHERS
================================================================================

  All launchers inherit LauncherItemBase fields:

  --- LauncherItemBase fields ---

  projectiles           FactionProjectile[]  Projectile prefabs per faction.
                                             First entry is the default.
  hueShiftProjectile    bool      Hue-shift projectile to faction colour.
  delayedWarningPrefab  GameObject  Warning indicator before firing (e.g., NPC
                                    telegraph attacks). Usually leave empty.
  muzzleFlashSprites    Sprite[]  Muzzle flash animation frames. Used by the
                                  MuzzleFlash component on the equippable prefab.
  soundEffect           SoundEffectPlayer.SoundEffect  Firing sound (see sec 12).

  -------------------------------------------------------------------------
  BasicLauncherItemBase          (Create > Star Vortex > Base > Item >
                                  Launcher - Basic)
  -------------------------------------------------------------------------
  Standard single-shot projectile weapon. Good for cannons, railguns, etc.

  resourcePath: "Base/Items/PrimaryWeapon" or "Base/Items/SecondaryWeapon"

  Level-up stats (added per level):
    statusEffectChance  float     Status effect chance increase per level.
    critChance          float     Critical hit chance increase per level.
    velocity            float     Projectile speed increase per level.
    reloadTime          float     Reload time change per level (negative = faster).

  Item data:
    launcher            BasicLauncher  The weapon's base stats. Expand in the
                                       Inspector to set: BaseDamage, BaseHealth,
                                       BaseReloadTime, BaseVelocity, etc.
    legendaries         LauncherLegendary[]  Legendary variants.

  -------------------------------------------------------------------------
  ScatterLauncherItemBase        (Launcher - Scatter)

================================================================================
  9. PREFAB SETUP - PROJECTILES
================================================================================

  Projectiles are GameObjects referenced by your weapon ScriptableObject.
  They need specific components to function.

  REQUIRED COMPONENTS (all projectile types):
  -------------------------------------------
  - SpriteRenderer        The projectile's visual.
  - Rigidbody2D           Physics body. Settings:
                             Gravity Scale = 0
                             Linear Drag = 0 (unless you want deceleration)
  - Collider2D            CircleCollider2D or BoxCollider2D.
                             Is Trigger = true (REQUIRED)
  - AutoDestroy           Handles pooling and lifetime.

  PROJECTILE COMPONENTS (pick one):
  ----------------------------------
  Projectile              Basic projectile. Deals damage on collision.
  ExplosiveProjectile     Explodes on impact for area damage.
                          Key fields: explosiveRadius (Unity units, x20 = metres)
  ClusterProjectile       Splits into sub-projectiles on impact/timer.
                          Key fields: projectile (sub-projectile prefab),
                          projectileCount, projectileHealth, projectileVelocity,
                          projectileAutoDestroy (lifetime in seconds)
  SeekingProjectile       Homes toward the nearest enemy.
  Missile                 Guided missile with turning speed.
  Mine                    Deploys and waits, explodes on proximity.
  FuzzyProjectile         Area/fuzzy damage projectile.
  BlackHoleProjectile     Creates a gravity well.
  LeechProjectile         Drains health from target.
  LaserProjectile         Instant-hit laser line.

  OPTIONAL COMPONENTS:
  --------------------
  - TrailRenderer         Visual trail behind the projectile.
  - ParticleSystem        Particle effects on the projectile.
  - Explosion             Add as a child GameObject. Plays on impact.

  MUZZLE FLASH SETUP:
  --------------------
  Muzzle flashes go on your EQUIPPABLE prefab (the gun model), not the
  projectile. Create a child GameObject named "Muzzle Flash" with:
  - SpriteRenderer
  - MuzzleFlash component (set sprites[] to your flash animation frames,
    and frameRate for animation speed)

  The component manifest system (section 11) automatically handles
  restoring game scripts like MuzzleFlash on your prefabs at runtime.


================================================================================
  10. PREFAB SETUP - EQUIPPABLE OBJECTS
================================================================================

  The gameObjectPrefab on your ScriptableObject is what gets attached to
  the player's ship. For weapons, this is the gun model.

  TYPICAL WEAPON EQUIPPABLE STRUCTURE:
  ------------------------------------
  Equippable (root GameObject)
    +-- Muzzle Flash (child)    SpriteRenderer + MuzzleFlash script
    +-- [other visual children]

  The root typically just has a SpriteRenderer for the weapon sprite.

  IMPORTANT: Game scripts (MuzzleFlash, Explosion, etc.) on mod prefabs
  will have missing script references because of Unity's GUID mismatch
  between DLL and source code. The component manifest system (section 11)
  handles this automatically - just set up your prefab with the components
  in the editor and they will be restored at runtime.


================================================================================
  11. COMPONENT MANIFEST SYSTEM
================================================================================

  When you build your AssetBundle, the SDK automatically scans all prefabs
  for components that come from Assembly-CSharp (game scripts). It saves
  their type names and field values to a components.json sidecar file.

  At runtime, the game's ModLoader reads this manifest and restores any
  missing components using reflection. This means:

  - You CAN add MuzzleFlash, Explosion, Projectile, and any other game
    script to your prefabs in the Unity editor.
  - When the bundle loads, if the script reference is broken (which it
    will be for game scripts), the manifest restores it automatically.
  - All serialized field values are preserved.

  YOU DON'T NEED TO DO ANYTHING SPECIAL. Just:
  1. Add game components to your prefabs normally in the editor.
  2. Build AssetBundles (the manifest generates automatically).
  3. Package your mod (components.json is copied automatically).


================================================================================
  12. SOUND EFFECTS
================================================================================

  SoundEffectPlayer.SoundEffect is a serializable class with these fields:

  audioClip             AudioClip   The audio file to play.
  volumeScale           float       Volume multiplier (default 1).
  loop                  bool        Whether the sound loops.
  pitchVariance         float       Random pitch variation (default 0.2).
  volumeVariance        float       Random volume variation (default 0.2).
  fadePitch             bool        Whether to fade pitch in.
  minPitch              float       Starting pitch for fade (default 0.2).
  maxPitch              float       Target pitch (default 1).
  fadeVolume            bool        Whether to fade volume in.
  minVolume             float       Starting volume for fade (default 0).
  maxVolume             float       Target volume (default 1).
  fadeSeconds           float       Fade duration in seconds (default 0.5).

  For mod audio, include your .wav or .ogg files in the AssetBundle and
  assign them to the audioClip field on your ScriptableObject.


================================================================================
  13. DAMAGE TYPES
================================================================================

  Damageable.DamageType enum:

    Kinetic       Physical/ballistic damage
    Cold          Ice/cryo damage
    Corrosive     Acid/chemical damage
    Electric      Lightning/EMP damage
    Thermal       Fire/heat damage
    Radiation     Nuclear/radiation damage

  Damage types affect:
  - Shield resistance bonuses
  - Status effects applied on hit
  - Visual effects and colours


================================================================================
  14. FACTIONS & FACTION-SPECIFIC ASSETS
================================================================================

  Several fields use "FactionImage" or "FactionProjectile" arrays to
  support different visuals per faction. The first entry in the array
  is always the default/fallback.

  FactionImage structure:
    faction     string    Faction identifier (e.g., "terran", "alien").
    image       Sprite    The sprite for that faction.

  FactionProjectile structure:
    faction     string    Faction identifier.
    gameObject  GameObject  The projectile prefab for that faction.

  For simple mods, you only need ONE entry with an empty faction string.
  The game uses it as the default when no faction match is found.


================================================================================
  15. LANGUAGE / TRANSLATIONS
================================================================================

  Every player-facing string needs a language entry. Set a unique
  languageKey on each ScriptableObject (e.g., "mymod.bananal").

  The game looks up:
    <languageKey>.name    Item display name
    <languageKey>.desc    Item description

  GENERATING LANGUAGE FILES:
  Star Vortex Mod > Generate Language File
  This scans all ItemBase assets and writes Assets/Languages/lang_enUS.json.

  MANUAL FORMAT (Assets/Languages/lang_enUS.json):
  {
    "mymod.bananal.name": "Banana Launcher",
    "mymod.bananal.desc": "Fires explosive bananas that split into mini bananas."
  }

  OTHER LANGUAGES:
  Create additional files: lang_de.json, lang_fr.json, lang_ja.json, etc.
  Only lang_enUS.json is required. Missing keys fall back to English.


================================================================================
  16. MOD.JSON REFERENCE
================================================================================

  Place mod.json in your Assets/ root directory (not in a subfolder).
  The build tools copy it into your mod package automatically.

  {
    "id": "com.yourname.modname",
    "name": "My Mod",
    "author": "Your Name",
    "version": "1.0.0",
    "description": "A description of what this mod does.",
    "gameVersion": "",
    "dependencies": [],
    "loadOrder": 0,
    "tags": ["content"]
  }

  Fields:
    id            string    REQUIRED. Unique reverse-domain identifier.
    name          string    Display name shown in the mod list.
    author        string    Your name or team name.
    version       string    Semantic version (major.minor.patch).
    description   string    Short description for the mod list.
    gameVersion   string    Target game version. Shows a warning if mismatched
                            but does not prevent loading.
    dependencies  string[]  Array of mod IDs that must load before yours.
    loadOrder     int       Lower numbers load first. Use 0 unless you need
                            specific ordering relative to other mods.
    tags          string[]  Freeform tags for categorisation.


================================================================================
  17. BUILDING & PACKAGING
================================================================================

  STEP 1: Assign AssetBundle names
  ---------------------------------
  Select your assets in the Project window. At the bottom of the Inspector,
  there is an "AssetBundle" dropdown. Set it to a name (e.g., "mymod").

  You MUST assign ALL assets that should be in the bundle:
  - ScriptableObject (.asset files)
  - Prefabs (.prefab files)
  - Sprites/textures used by prefabs
  - Audio clips used by sound effects

  Assets NOT assigned to a bundle will NOT be included in your mod.

  STEP 2: Build AssetBundles
  ---------------------------
  Star Vortex Mod > Build AssetBundles

  This builds all assigned assets into bundle files and generates the
  component manifest (components.json).

  STEP 3: Edit mod.json
  ----------------------
  Make sure Assets/mod.json has your mod's correct details.

  STEP 4: Generate Language File
  -------------------------------
  Star Vortex Mod > Generate Language File

  Creates lang_enUS.json from your ScriptableObject name/description fields.

  STEP 5: Package Mod
  --------------------
  Star Vortex Mod > Package Mod

  Creates ModPackage/<ModName>/ containing:
    mod.json
    <bundlename>.bundle
    components.json (if generated)
    lang_enUS.json (and any other lang_*.json)
    icon.png (if found anywhere in Assets/)
    <YourAssembly>.dll (if you have code mods)

  STEP 6: Install
  ----------------
  Copy the mod folder to: StarVortex_Data/Mods/<ModName>/
  Launch Star Vortex. Check the Mod Panel for load status.


================================================================================
  18. CODE MODS (HARMONY)
================================================================================

  Code mods use HarmonyX to patch game methods at runtime.

  SETUP:
  1. Create a folder for your scripts.
  2. Create an Assembly Definition (.asmdef) in that folder.
     In its Inspector:
       - Tick "Override References"
       - Add references: Assembly-CSharp, 0Harmony
  3. Create a C# class implementing IStarVortexMod:

     using HarmonyLib;
     using StarVortex;
     using UnityEngine;

     public class MyMod : IStarVortexMod
     {
         public void Init(ModInfo modInfo, Harmony harmony)
         {
             Debug.Log("[MyMod] Loaded!");
             harmony.PatchAll();
         }

         public void OnGameLoaded()
         {
             // Called after all game systems are initialized
         }

         public void Shutdown()
         {
             // Called when the game exits
         }
     }

  4. Write Harmony patches as normal:

     [HarmonyPatch(typeof(SomeClass), "SomeMethod")]
     public class MyPatch
     {
         static void Prefix() { /* runs before */ }
         static void Postfix() { /* runs after */ }
     }

  5. Your compiled DLL is at Library/ScriptAssemblies/<YourAssembly>.dll
     Package Mod copies it automatically if it detects an .asmdef.

  For Harmony documentation: https://harmony.pardeike.net/


================================================================================
  19. UNIT CONVERSION
================================================================================

  1 Unity unit = 20 metres in-game.

  When setting ranges, radii, velocities, etc. in the Inspector:
    Value 1.0  =  20m
    Value 5.0  = 100m
    Value 10.0 = 200m

  Examples:
    explosiveRadius: 4  = 80m blast radius
    maxRange: 15        = 300m weapon range
    velocity: 20        = 400m/s projectile speed


================================================================================
  20. TROUBLESHOOTING
================================================================================

  ITEM DOESN'T APPEAR IN EQUIPMENT LIST
  -> Check resourcePath matches exactly (see section 2).
  -> Make sure npcUseOnly is false and noSandbox is false.
  -> Make sure the ScriptableObject is assigned to an AssetBundle.
  -> Rebuild AssetBundles after any changes.

  "MISSING" REFERENCES ON GAMECONTENT ASSETS
  -> This is expected. Prefab, sprite, material, and audio references
     show as Missing because visual assets are not part of the import.
  -> You can safely ignore these. When your mod overrides a base game
     asset, the game automatically inherits all missing non-SO
     references (prefabs, sprites, materials, audio) from the original.
  -> Just change the values you care about and build. Everything else
     carries over from the base game at runtime.
  -> To replace a visual asset, create your own in your mod project,
     assign it to the field, and include it in your AssetBundle.

  OVERRIDE REPLACES THE WRONG ASSET
  -> Overrides are matched by name AND resourcePath together.
  -> Do NOT change the resourcePath when duplicating a GameContent asset.
  -> Some asset names exist in multiple folders (e.g., same squadron
     name in different factions). resourcePath disambiguates them.

  MISSING SCRIPT ON PREFAB COMPONENTS
  -> This is expected for game scripts (MuzzleFlash, Explosion, etc.).
  -> The component manifest system restores them at runtime.
  -> Make sure you ran Build AssetBundles (generates components.json).
  -> Make sure components.json is in your mod folder.

  ICON NOT SHOWING IN MOD LIST
  -> Place icon.png anywhere in your Assets/ folder.
  -> It must be named exactly "icon.png".
  -> Recommended size: 256x256 pixels.

  NO ASSETS IN MOD PACKAGE
  -> You must assign assets to an AssetBundle name first.
  -> Run Build AssetBundles BEFORE Package Mod.

  BUNDLE FAILS TO LOAD
  -> Your Unity version MUST be exactly 2022.3.62f2.
  -> Other versions produce incompatible AssetBundles.

  NO SOUND
  -> Make sure your AudioClip files are assigned to the AssetBundle.
  -> Check volumeScale is not 0.

  LANGUAGE TEXT SHOWS KEY INSTEAD OF NAME
  -> Run Generate Language File after setting languageKey.
  -> Make sure lang_enUS.json is in your mod folder.
  -> Check that languageKey matches between the .asset and .json.

  MOD DOESN'T LOAD AT ALL
  -> Check mod.json exists and has valid JSON.
  -> Check Player.log for [ModLoader] error messages.
  -> Make sure the mod folder is directly inside StarVortex_Data/Mods/.

  CHECKING LOGS
  -> Player.log location:
     Windows: %USERPROFILE%\AppData\LocalLow\<Company>\Star Vortex\Player.log
  -> Search for "[ModLoader]" to see mod loading messages.
  -> The in-game Mod Panel also shows load status and errors.
